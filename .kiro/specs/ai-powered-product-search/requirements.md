# AI-Powered Product Search & Recommendations - Requirements Specification

## Introduction

The AI-Powered Product Search & Recommendations feature enhances the eShopOnWeb e-commerce platform with semantic search capabilities and personalized product recommendations. This feature leverages Azure OpenAI Embeddings to understand customer intent beyond keyword matching, enabling customers to discover products more effectively through natural language queries, typo-tolerant search, and personalized suggestions based on browsing history and behavior patterns.

The system will integrate seamlessly with the existing Clean Architecture, utilizing the ApplicationCore for business logic, Infrastructure for data persistence, and PublicApi for FastEndpoints-based API exposure. The feature addresses key customer pain points: difficulty finding products, generic search results, and lack of personalization.

---

## Glossary

- **Semantic Search**: Search that understands the meaning and intent behind queries, not just keyword matching
- **Product Embedding**: A numerical vector representation of a product's attributes, description, and metadata generated by Azure OpenAI
- **Recommendation Engine**: The system component that generates personalized product suggestions based on user behavior and preferences
- **Browsing History**: The record of products a user has viewed, including timestamps and duration
- **User Profile**: Aggregated data about a user including preferences, purchase history, browsing patterns, and demographic information
- **Relevance Score**: A numerical value (0-1) indicating how well a product matches a search query or recommendation criteria
- **Embedding Vector**: A high-dimensional numerical representation of semantic meaning
- **Catalog Item**: A product in the eShopOnWeb system with attributes like name, description, price, category, and inventory
- **Search Query**: A user-submitted text string representing their product search intent
- **Recommendation Context**: The set of factors used to generate recommendations (browsing history, purchase history, user profile, current session)
- **Cold Start Problem**: The challenge of making recommendations for new users with no browsing or purchase history
- **Personalization**: Tailoring product suggestions and search results to individual user preferences and behavior
- **Fallback Search**: Non-semantic search mechanism used when semantic search is unavailable or fails
- **Cache**: In-memory storage of frequently accessed embeddings and recommendations to reduce API calls
- **Typo Tolerance**: The system's ability to understand and correct misspelled search queries
- **Product Metadata**: Structured information about a product including category, brand, price, ratings, and inventory status
- **Recommendation Widget**: UI component displaying suggested products to users
- **Search Analytics**: Data collected about search queries, results, and user interactions for analysis and improvement
- **Azure OpenAI**: Microsoft's managed service providing access to OpenAI's language models and embedding APIs
- **Vector Database**: Storage system optimized for storing and querying high-dimensional embedding vectors
- **Semantic Kernel**: Microsoft's .NET SDK for orchestrating AI operations and integrating with language models

## Requirements

### Requirement 1: Semantic Product Search

**User Story:** As a customer, I want to search for products using natural language queries, so that I can find products even when I don't know exact product names or specifications.

#### Acceptance Criteria

1. WHEN a customer submits a search query, THE SearchService SHALL convert the query into an embedding vector using Azure OpenAI Embeddings API
2. WHEN an embedding vector is generated, THE SearchService SHALL compare it against stored product embeddings in the database using cosine similarity
3. WHEN a search is performed, THE SearchService SHALL return a ranked list of products sorted by relevance score in descending order
4. WHEN a search query contains typos or misspellings, THE SearchService SHALL still return relevant results by correcting the query or using fuzzy matching
5. WHEN a search returns no results, THE SearchService SHALL return an empty result set with a message indicating no products matched the query
6. WHEN a customer searches for a product, THE SearchService SHALL complete the search and return results within 500 milliseconds
7. WHEN a search query is submitted, THE SearchService SHALL log the query, results count, and top result for analytics purposes
8. WHEN a search query is fewer than 2 characters, THE SearchService SHALL reject the query and return a validation error
9. WHEN a search query exceeds 500 characters, THE SearchService SHALL truncate it to 500 characters and proceed with the search
10. WHEN a search is performed, THE SearchService SHALL filter results to only include products with active inventory status

### Requirement 2: Product Embedding Generation and Storage

**User Story:** As a system administrator, I want product embeddings to be automatically generated and stored, so that semantic search can function efficiently without manual intervention.

#### Acceptance Criteria

1. WHEN a new product is created in the catalog, THE EmbeddingService SHALL automatically generate an embedding vector for the product using product name, description, category, and brand
2. WHEN a product is updated, THE EmbeddingService SHALL regenerate the embedding vector and update the stored embedding
3. WHEN an embedding is generated, THE EmbeddingService SHALL store it in the ProductEmbeddings table with the product ID, embedding vector, and creation timestamp
4. WHEN embeddings are generated, THE EmbeddingService SHALL cache frequently accessed embeddings in memory to reduce database queries
5. WHEN the cache reaches capacity, THE EmbeddingService SHALL evict least-recently-used embeddings using LRU eviction policy
6. WHEN a product is deleted, THE EmbeddingService SHALL remove the corresponding embedding from storage
7. WHEN embedding generation fails, THE EmbeddingService SHALL log the error and retry up to 3 times with exponential backoff
8. WHEN embeddings are stored, THE EmbeddingService SHALL validate that the embedding vector has the correct dimensionality (1536 dimensions for text-embedding-3-small)
9. WHEN a batch of products is imported, THE EmbeddingService SHALL generate embeddings asynchronously in background jobs to avoid blocking the import process
10. WHEN embeddings are generated, THE EmbeddingService SHALL track the number of API calls and cost for monitoring and optimization

### Requirement 3: Personalized Product Recommendations Based on Browsing History

**User Story:** As a customer, I want to see personalized product recommendations based on products I've viewed, so that I can discover related items that match my interests.

#### Acceptance Criteria

1. WHEN a customer views a product, THE BrowsingHistoryService SHALL record the product ID, timestamp, and session ID
2. WHEN a customer has viewed at least 3 products, THE RecommendationEngine SHALL generate personalized recommendations based on browsing history
3. WHEN recommendations are generated, THE RecommendationEngine SHALL identify products similar to those in the browsing history using embedding similarity
4. WHEN recommendations are generated, THE RecommendationEngine SHALL return a ranked list of up to 10 products sorted by relevance score
5. WHEN a customer has no browsing history, THE RecommendationEngine SHALL return trending products or popular products as fallback recommendations
6. WHEN recommendations are retrieved, THE RecommendationEngine SHALL exclude products already in the customer's shopping cart
7. WHEN recommendations are retrieved, THE RecommendationEngine SHALL exclude products the customer has already purchased
8. WHEN recommendations are generated, THE RecommendationEngine SHALL complete the operation within 300 milliseconds
9. WHEN recommendations are generated, THE RecommendationEngine SHALL cache results for 1 hour to reduce computation overhead
10. WHEN a customer's browsing history is cleared, THE RecommendationEngine SHALL clear cached recommendations for that customer

### Requirement 4: "You Might Also Like" Recommendations on Product Detail Pages

**User Story:** As a customer viewing a product, I want to see related product recommendations, so that I can discover complementary or similar items without additional searching.

#### Acceptance Criteria

1. WHEN a customer views a product detail page, THE RecommendationEngine SHALL generate "You Might Also Like" recommendations based on the current product
2. WHEN recommendations are generated for a product, THE RecommendationEngine SHALL identify products with similar embeddings using cosine similarity
3. WHEN recommendations are generated, THE RecommendationEngine SHALL return 4-6 related products sorted by relevance score
4. WHEN recommendations are generated, THE RecommendationEngine SHALL exclude the current product from results
5. WHEN recommendations are generated, THE RecommendationEngine SHALL prioritize products in the same category or price range
6. WHEN recommendations are displayed, THE RecommendationWidget SHALL render product cards with image, name, price, and rating
7. WHEN a customer clicks on a recommended product, THE RecommendationWidget SHALL track the click and update recommendation scores
8. WHEN recommendations are generated, THE RecommendationEngine SHALL complete the operation within 200 milliseconds
9. WHEN a product has no similar products, THE RecommendationEngine SHALL return an empty result set and the widget SHALL not display
10. WHEN recommendations are generated, THE RecommendationEngine SHALL cache results for 24 hours to reduce API calls

### Requirement 5: Personalized Homepage Recommendations

**User Story:** As a customer visiting the homepage, I want to see personalized product suggestions tailored to my interests, so that I can quickly discover products relevant to me.

#### Acceptance Criteria

1. WHEN a returning customer visits the homepage, THE RecommendationEngine SHALL generate personalized recommendations based on their user profile
2. WHEN recommendations are generated for the homepage, THE RecommendationEngine SHALL consider browsing history, purchase history, and user preferences
3. WHEN recommendations are generated, THE RecommendationEngine SHALL return 8-12 products organized into recommendation categories (e.g., "Based on Your Browsing", "Trending Now", "New Arrivals")
4. WHEN a new customer visits the homepage, THE RecommendationEngine SHALL display trending products, new arrivals, and popular categories as fallback recommendations
5. WHEN recommendations are generated, THE RecommendationEngine SHALL complete the operation within 500 milliseconds
6. WHEN recommendations are displayed, THE RecommendationWidget SHALL render product cards with image, name, price, rating, and a "View Details" button
7. WHEN a customer clicks on a recommended product, THE RecommendationWidget SHALL track the click for analytics and model improvement
8. WHEN recommendations are generated, THE RecommendationEngine SHALL cache results for 2 hours to reduce computation overhead
9. WHEN a customer is logged in, THE RecommendationEngine SHALL use their user ID to personalize recommendations
10. WHEN a customer is not logged in, THE RecommendationEngine SHALL use session-based recommendations based on current browsing history

### Requirement 6: Search Query Correction and Typo Tolerance

**User Story:** As a customer, I want the search system to understand and correct my typos, so that I can find products even if I misspell search terms.

#### Acceptance Criteria

1. WHEN a search query contains a misspelled word, THE QueryCorrectionService SHALL identify the misspelling and suggest corrections
2. WHEN a correction is suggested, THE QueryCorrectionService SHALL use the corrected query for semantic search
3. WHEN a query is corrected, THE SearchService SHALL display the corrected query to the customer (e.g., "Showing results for 'running shoes'")
4. WHEN a query has multiple possible corrections, THE QueryCorrectionService SHALL select the correction with the highest confidence score
5. WHEN a query is corrected, THE SearchService SHALL still return results for the original query if the corrected query returns no results
6. WHEN a query contains common misspellings, THE QueryCorrectionService SHALL correct them with at least 95% accuracy
7. WHEN a query is corrected, THE SearchService SHALL log both the original and corrected queries for analytics
8. WHEN a query correction is performed, THE QueryCorrectionService SHALL complete the operation within 100 milliseconds
9. WHEN a query contains multiple words, THE QueryCorrectionService SHALL correct each word independently
10. WHEN a query is a proper noun or brand name, THE QueryCorrectionService SHALL not attempt to correct it

### Requirement 7: Search Analytics and Logging

**User Story:** As a business analyst, I want to track search queries and user interactions, so that I can understand customer search behavior and improve the search experience.

#### Acceptance Criteria

1. WHEN a search is performed, THE SearchAnalyticsService SHALL log the query, customer ID, timestamp, number of results, and top result
2. WHEN a search result is clicked, THE SearchAnalyticsService SHALL log the click, product ID, and ranking position
3. WHEN a recommendation is displayed, THE SearchAnalyticsService SHALL log the recommendation type, products shown, and timestamp
4. WHEN a recommendation is clicked, THE SearchAnalyticsService SHALL log the click, product ID, and recommendation type
5. WHEN analytics data is collected, THE SearchAnalyticsService SHALL store it in the SearchAnalytics table for later analysis
6. WHEN analytics queries are performed, THE SearchAnalyticsService SHALL return results within 1 second for dashboard queries
7. WHEN analytics data is collected, THE SearchAnalyticsService SHALL not block the search or recommendation operations
8. WHEN analytics data is stored, THE SearchAnalyticsService SHALL retain data for at least 12 months
9. WHEN analytics data is queried, THE SearchAnalyticsService SHALL provide aggregated metrics (e.g., top searches, click-through rates, conversion rates)
10. WHEN analytics data is collected, THE SearchAnalyticsService SHALL comply with GDPR and CCPA privacy regulations by anonymizing customer identifiers after 90 days

### Requirement 8: API Endpoints for Search and Recommendations

**User Story:** As a frontend developer, I want well-defined API endpoints for search and recommendations, so that I can integrate these features into the user interface.

#### Acceptance Criteria

1. THE PublicApi SHALL expose a POST endpoint at `/api/products/search` that accepts a search query and returns ranked product results
2. THE PublicApi SHALL expose a GET endpoint at `/api/products/recommendations` that returns personalized recommendations for the authenticated customer
3. THE PublicApi SHALL expose a GET endpoint at `/api/products/{productId}/related` that returns "You Might Also Like" recommendations for a specific product
4. THE PublicApi SHALL expose a GET endpoint at `/api/products/trending` that returns trending products based on search and purchase analytics
5. WHEN a search request is received, THE SearchEndpoint SHALL validate the query parameter and return a 400 Bad Request if invalid
6. WHEN a search request is received, THE SearchEndpoint SHALL return a 200 OK response with a JSON array of product objects
7. WHEN a recommendations request is received, THE RecommendationsEndpoint SHALL return a 200 OK response with a JSON array of product objects
8. WHEN a recommendations request is received by an unauthenticated user, THE RecommendationsEndpoint SHALL return a 401 Unauthorized response
9. WHEN an API request fails, THE Endpoint SHALL return a 500 Internal Server Error with an error message and request ID for debugging
10. WHEN an API request is received, THE Endpoint SHALL log the request, response status, and response time for monitoring

### Requirement 9: Integration with Existing Product Catalog

**User Story:** As a system administrator, I want the AI search and recommendations to work seamlessly with the existing product catalog, so that no changes to the catalog structure are required.

#### Acceptance Criteria

1. WHEN the system starts, THE EmbeddingService SHALL load all active products from the CatalogItem table
2. WHEN products are loaded, THE EmbeddingService SHALL generate embeddings for any products without existing embeddings
3. WHEN a product is updated in the catalog, THE EmbeddingService SHALL automatically regenerate its embedding
4. WHEN a product is deleted from the catalog, THE EmbeddingService SHALL remove its embedding from storage
5. WHEN searching or generating recommendations, THE SearchService SHALL only include products with active status and available inventory
6. WHEN a product's price changes, THE RecommendationEngine SHALL consider the new price in recommendation ranking
7. WHEN a product's category changes, THE RecommendationEngine SHALL update the product's embedding to reflect the new category
8. WHEN the system accesses product data, THE SearchService SHALL use the existing CatalogItem entity without modifications
9. WHEN embeddings are generated, THE EmbeddingService SHALL use product name, description, category, and brand from the CatalogItem table
10. WHEN the catalog is updated, THE EmbeddingService SHALL maintain backward compatibility with existing product data

### Requirement 10: Performance and Scalability

**User Story:** As a platform operator, I want the search and recommendation system to perform efficiently under load, so that customer experience remains responsive during peak traffic.

#### Acceptance Criteria

1. WHEN a search query is submitted, THE SearchService SHALL return results within 500 milliseconds for 95% of requests
2. WHEN recommendations are generated, THE RecommendationEngine SHALL complete within 300 milliseconds for 95% of requests
3. WHEN embeddings are cached, THE SearchService SHALL retrieve cached embeddings within 10 milliseconds
4. WHEN the system handles 1000 concurrent users, THE SearchService SHALL maintain response times within acceptable limits
5. WHEN embeddings are stored, THE Database SHALL support efficient similarity searches using vector indexing
6. WHEN API calls are made to Azure OpenAI, THE System SHALL implement caching to reduce redundant API calls by at least 80%
7. WHEN the system is under load, THE SearchService SHALL gracefully degrade by returning cached results or fallback recommendations
8. WHEN embeddings are generated, THE System SHALL batch process embeddings to reduce API calls and costs
9. WHEN the system scales, THE SearchService SHALL support horizontal scaling by using distributed caching
10. WHEN the system monitors performance, THE System SHALL track API response times, cache hit rates, and error rates for optimization

### Requirement 11: Security and Data Privacy

**User Story:** As a customer, I want my personal data and search history to be protected, so that my privacy is respected and my data is secure.

#### Acceptance Criteria

1. WHEN a customer's search query is logged, THE System SHALL encrypt the query data at rest using AES-256 encryption
2. WHEN search data is transmitted, THE System SHALL use HTTPS/TLS 1.2 or higher for all API communications
3. WHEN a customer's browsing history is stored, THE System SHALL associate it with their user ID and not expose it to other users
4. WHEN a customer requests data deletion, THE System SHALL remove their search history and browsing history within 30 days
5. WHEN analytics data is collected, THE System SHALL anonymize customer identifiers after 90 days to comply with GDPR
6. WHEN embeddings are generated, THE System SHALL not store raw customer data in the embedding vectors
7. WHEN API calls are made to Azure OpenAI, THE System SHALL not transmit customer personal information (email, phone, address) to external services
8. WHEN the system accesses customer data, THE System SHALL enforce role-based access control (RBAC) to restrict access to authorized personnel
9. WHEN audit logs are maintained, THE System SHALL log all access to customer search and browsing data for compliance auditing
10. WHEN the system handles sensitive data, THE System SHALL comply with GDPR, CCPA, and other applicable data protection regulations

### Requirement 12: Error Handling and Fallback Mechanisms

**User Story:** As a customer, I want the search and recommendation features to work reliably even when external services are unavailable, so that I can still browse and search for products.

#### Acceptance Criteria

1. WHEN Azure OpenAI API is unavailable, THE SearchService SHALL fall back to keyword-based search using the existing search functionality
2. WHEN embedding generation fails, THE System SHALL log the error and retry up to 3 times with exponential backoff before falling back
3. WHEN a recommendation request fails, THE RecommendationEngine SHALL return trending or popular products as fallback recommendations
4. WHEN the cache is unavailable, THE System SHALL query the database directly for embeddings
5. WHEN a database query fails, THE System SHALL return a 503 Service Unavailable response with a retry-after header
6. WHEN an API request times out, THE System SHALL return a 504 Gateway Timeout response and log the timeout for monitoring
7. WHEN the system detects a service degradation, THE System SHALL alert the operations team and log the incident
8. WHEN a customer experiences an error, THE System SHALL display a user-friendly error message without exposing technical details
9. WHEN the system recovers from an error, THE System SHALL resume normal operation without manual intervention
10. WHEN errors occur, THE System SHALL maintain data consistency and not corrupt existing search or recommendation data

### Requirement 13: User Interface Components

**User Story:** As a frontend developer, I want reusable UI components for search and recommendations, so that I can integrate these features consistently across the application.

#### Acceptance Criteria

1. THE Web project SHALL include a SearchBox.razor component that accepts user input and submits search queries
2. THE Web project SHALL include a SearchResults.razor component that displays ranked search results with product cards
3. THE Web project SHALL include a RecommendationCarousel.razor component that displays recommended products in a carousel format
4. THE Web project SHALL include a YouMightAlsoLike.razor component that displays related products on product detail pages
5. WHEN a search result is displayed, THE SearchResults component SHALL show product image, name, price, rating, and a "View Details" button
6. WHEN a recommendation is displayed, THE RecommendationCarousel component SHALL show product image, name, price, and a "View Details" button
7. WHEN a customer clicks on a product, THE Component SHALL navigate to the product detail page
8. WHEN recommendations are loading, THE Component SHALL display a loading indicator
9. WHEN no results are found, THE Component SHALL display a message indicating no products matched the search or recommendation criteria
10. WHEN the component is rendered, THE Component SHALL be responsive and work on mobile, tablet, and desktop devices

### Requirement 14: Admin Dashboard for Search and Recommendation Analytics

**User Story:** As a business administrator, I want to view analytics about search queries and recommendation performance, so that I can understand customer behavior and optimize the system.

#### Acceptance Criteria

1. THE BlazorAdmin project SHALL include a SearchAnalyticsDashboard.razor component that displays search analytics
2. WHEN the dashboard is loaded, THE Dashboard SHALL display top search queries, search volume trends, and click-through rates
3. WHEN the dashboard is loaded, THE Dashboard SHALL display recommendation performance metrics (impressions, clicks, conversion rates)
4. WHEN the dashboard is loaded, THE Dashboard SHALL display trending products based on search and purchase data
5. WHEN the dashboard is loaded, THE Dashboard SHALL display search query corrections and their effectiveness
6. WHEN the dashboard is loaded, THE Dashboard SHALL allow filtering by date range, product category, and customer segment
7. WHEN the dashboard is loaded, THE Dashboard SHALL display charts and graphs for visual analysis
8. WHEN the dashboard is loaded, THE Dashboard SHALL complete loading within 2 seconds
9. WHEN an admin views the dashboard, THE Dashboard SHALL require admin role authorization
10. WHEN the dashboard displays data, THE Dashboard SHALL not expose individual customer identities or personal information

### Requirement 15: Configuration and Deployment

**User Story:** As a DevOps engineer, I want to configure the AI search and recommendation system for different environments, so that I can deploy it to development, staging, and production.

#### Acceptance Criteria

1. WHEN the application starts, THE System SHALL read Azure OpenAI configuration from appsettings.json or environment variables
2. WHEN the system is configured, THE System SHALL support different Azure OpenAI models for different environments (e.g., text-embedding-3-small for dev, text-embedding-3-large for prod)
3. WHEN the system is deployed, THE System SHALL support configurable cache sizes and TTLs for different environments
4. WHEN the system is deployed, THE System SHALL support configurable API rate limits and timeouts
5. WHEN the system is deployed, THE System SHALL support feature flags to enable/disable search and recommendation features
6. WHEN the system is configured, THE System SHALL validate all required configuration values at startup and fail fast if missing
7. WHEN the system is deployed, THE System SHALL log all configuration values (excluding secrets) for debugging
8. WHEN the system is deployed, THE System SHALL support database migrations for new tables (ProductEmbeddings, SearchAnalytics, etc.)
9. WHEN the system is deployed, THE System SHALL support rollback to previous versions without data loss
10. WHEN the system is deployed, THE System SHALL document all configuration options and their default values

## Data Requirements

### New Database Tables

**ProductEmbeddings Table**
- ProductEmbeddingId (PK, int)
- CatalogItemId (FK, int)
- EmbeddingVector (nvarchar(max)) - JSON array of 1536 floats
- CreatedDate (datetime)
- UpdatedDate (datetime)
- Indexes: CatalogItemId, CreatedDate

**SearchAnalytics Table**
- SearchAnalyticsId (PK, int)
- CustomerId (FK, int, nullable)
- SessionId (uniqueidentifier)
- SearchQuery (nvarchar(500))
- CorrectedQuery (nvarchar(500), nullable)
- ResultCount (int)
- TopResultProductId (int, nullable)
- ResponseTimeMs (int)
- CreatedDate (datetime)
- Indexes: CustomerId, SessionId, CreatedDate

**RecommendationAnalytics Table**
- RecommendationAnalyticsId (PK, int)
- CustomerId (FK, int, nullable)
- SessionId (uniqueidentifier)
- RecommendationType (nvarchar(50)) - "browsing_history", "product_detail", "homepage"
- ProductsShown (nvarchar(max)) - JSON array of product IDs
- ProductClicked (int, nullable)
- ClickPosition (int, nullable)
- CreatedDate (datetime)
- Indexes: CustomerId, SessionId, CreatedDate

**BrowsingHistory Table**
- BrowsingHistoryId (PK, int)
- CustomerId (FK, int)
- CatalogItemId (FK, int)
- SessionId (uniqueidentifier)
- ViewDurationSeconds (int)
- CreatedDate (datetime)
- Indexes: CustomerId, CatalogItemId, CreatedDate

## Success Criteria and Metrics

### Customer Experience Metrics

- **Search Success Rate**: Percentage of searches resulting in a product view or purchase (Target: >40%)
- **Recommendation Click-Through Rate**: Percentage of displayed recommendations clicked (Target: >8%)
- **Average Order Value**: Impact of recommendations on order value (Target: +15% for customers with recommendations)
- **Customer Satisfaction**: NPS score for search and recommendation features (Target: >50)
- **Search Query Correction Accuracy**: Percentage of corrections that improve search results (Target: >95%)

### Business Metrics

- **Conversion Rate**: Percentage of visitors who purchase (Target: +10% improvement)
- **Support Ticket Reduction**: Reduction in product discovery-related support tickets (Target: -30%)
- **Revenue Impact**: Incremental revenue from AI features (Target: +5% of total revenue)
- **Customer Retention**: Repeat purchase rate for customers using AI features (Target: +20%)
- **Average Session Duration**: Time spent on site (Target: +25%)

### Technical Metrics

- **API Response Time (p95)**: 95th percentile response time for search and recommendations (Target: <500ms)
- **Cache Hit Rate**: Percentage of requests served from cache (Target: >80%)
- **System Uptime**: Availability during business hours (Target: 99.5%)
- **Error Rate**: Percentage of failed requests (Target: <0.5%)
- **API Cost per Transaction**: Cost of Azure OpenAI API calls (Target: <$0.01 per search)

### Quality Metrics

- **Embedding Quality**: Cosine similarity between semantically similar products (Target: >0.85)
- **Recommendation Relevance**: Percentage of recommendations rated as relevant by users (Target: >70%)
- **Search Result Relevance**: Percentage of search results rated as relevant by users (Target: >75%)
- **False Positive Rate**: Percentage of irrelevant recommendations (Target: <10%)
